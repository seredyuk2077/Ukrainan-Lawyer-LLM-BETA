# U4 CacheRAG — Pipeline

## Stages (A–E)

- **A. Query understanding** — NFC, whitespace, typo fix; anchors from taxonomy only. Intent/domain from query_profile. **U2 domain source:** heuristic (rules) or LLM; optional **U2 AI domain classifier** (Phase 6, OFF by default): when heuristic confidence < 0.55 or domain === general, max 1 call/run, returns taxonomy family keys only; query_profile.domainHint + domain_confidence + domain_candidates_top2; trace meta.u2_domain, meta.u2_ai_domain.
- **A.1 Structural citation anchors** — U4 treats Ukrainian structural selectors (`ст./ч./п./пп./абз./примітка`) as first-class query evidence. Parsing is Cyrillic-safe, normalizes dotted selector variants (`п.п.`, `ч.ч.`), and note-only mentions without a note number no longer count as full explicit selectors. The signal flows into chunk scoring, diversity, golden eval, and query-rewrite policy so `пунктом 12 Правил ...` is not mistaken for a generic natural-language query.
- **A.2 Exact act identifiers** — Structured act identifiers (`2811-20`, `115/2015`, `100-95-п`, `v0003359-26`) are first-class retrieval evidence. U4 preserves them through taxonomy signals, query shaping, act ranking, and honesty logic instead of losing them in generic tokenization. This is required for scale, because many prod queries will be short act-id probes against a partial LLDBI corpus.
- **A.3 Grounded exact aliases/titles** — Short exact act aliases and titles (`ЦПК`, `КУзПБ`, `закон 1023-12`, `Постанова 1178`) are treated separately from fuzzy alias-hit volume. Exact one-act grounding from query text or extracted `law_title`/`act_abbrev` can skip unnecessary rewrite/fanout and can confirm explicit subordinate-act scope without pretending every short alias query is “strong taxonomy”.
- **A.3a Split logical-act grounding** — Exact alias grounding also covers the case where one legal act is indexed as several `rada_nreg` slices. If all exact alias matches collapse to one logical act family (`КУпАП` split by article ranges), taxonomy may emit one grounded family signal instead of treating the query as unresolved alias noise.
- **A.3b Repeal-title grounding** — Amendment/repeal subordinate acts often have titles like `Про визнання таким, що втратило чинність, ... № 1478`, while lawyers ask shorter variants like `розпорядження про втрату чинності № 1478`. Runtime now derives compact repeal aliases from those titles at taxonomy-load time, so explicit repeal/revocation questions can ground deterministically without a per-act rule list.
- **A.3d Title-fragment grounding** — Compact LLDBI-first queries can also ground through a unique title fragment when taxonomy converges to one indexed act (`розпорядження про закриття дисциплінарного провадження`). This stays deterministic and cheap; it is not a fuzzy domain heuristic.
- **A.3e Shared descriptive-title classifier** — The same descriptive-title / interrogative-act-locator classifier is reused across U2 enrichment, goal splitting, taxonomy grounding, and single-goal scope recovery. This keeps long title-locator behavior consistent and prevents U2 from trying title-fragment grounding on arbitrary long natural-language questions.
- **A.3f Stable quoted-title grounding** — Quoted law titles are also deterministic act-scope evidence, including short official names like `«Про медіацію»`. Quoted-title extraction must be stateless across repeated calls; otherwise explicit law-title queries can randomly lose strict grounding and incorrectly drift onto semantic neighbors.
- **A.3g Broad decision-envelope compatibility** — Explicit subordinate-act queries are allowed to use broader non-primary decision language (`урядове рішення`, `акт Кабміну`, `рішення уряду`) when cue class plus title/number identity still converge to one indexed subordinate act. This stays bounded to deterministic identity convergence; it is not a free topical synonym boost.
- **A.3h Current-law successor preference** — If a soft quoted-title/title-fragment query matches several indexed acts from one logical same-title family, and the query does not pin a historical number/date/month, taxonomy may prefer the unique `in_force` successor. This prevents honest current-law questions from drifting into stale predecessor acts.
- **A.3a Grounded single-act split guard** — Taxonomy-cluster multi-goal split is forbidden when taxonomy already converged to one exact/grounded act. This keeps explicit subordinate-act queries (`Указ про призначення Кубраков`, `Постанова 1178`) in a cheap single-goal path instead of letting category noise create fake substance/procedure goals.
- **A.3b Subordinate-act scope cues** — Grounded act-scope detection now covers not only laws/codes but also subordinate acts and raw act identifiers (`за постановою № 1178`, `2811-20`, `наказ № ...`). Це важливо для large partial corpora, де short act-scoped queries мають залишатися cheap single-goal runs, а не перетворюватися на noisy generic procedure retrieval.
- **A.3c Short act-number references in U2/U3** — Short structural references like `ПКМ №100`, `постанова КМУ №1178`, `наказ МОЗ №385` are treated as structural act-scope cues and must not trigger `ambiguity_hard` / DocList fanout by themselves.
- **B. Act candidate generation** — Taxonomy (alias/keyword/topic/title/summary) + Qdrant acts search + evidence from reranked top hits. U2/LLDBI hints лишаються soft prior only; сильний ранній chunk evidence може підняти правильний акт навіть при помилковому domain hint. Runtime: `retrieval/act-candidate-ranking.ts`.
- **B.1 Evidence-act metadata backfill** — When final chunk evidence surfaces an act that taxonomy/acts-search did not rank high enough, U4 backfills it through the same metadata scorer (`title`, `summary`, `keywords`, `topics`, `validity_status`) instead of injecting a zero-score `chunks_evidence_meta` tail. This is required so single-goal scope recovery and honesty policy reason about real semantic support, not only about the fact that the act appeared in chunk evidence.
- **B.0 Exact-id convergence** — If query/taxonomy converges on one explicit structured act identifier, taxonomy strength is considered strong even without broad alias/topic evidence. This allows U4 to skip unnecessary rewrite and to keep short exact-id runs cheap.
- **B.0a Grounded-act convergence** — Strong taxonomy support now comes from one-act grounding (`structured id` or `exact alias/title`) rather than from raw alias-hit volume. This keeps short explicit act queries cheap while avoiding false “strong taxonomy” on ambiguous numbered aliases.
- **B.0ab Logical-family exact aliases** — When exact alias/title matches resolve to several indexed entries but one logical act family, U4 may choose a stable representative for grounding/trace purposes while still keeping the rest of the family in act candidates for later within-act/article competition. This is how compact aliases stay cheap without pretending the corpus has only one physical document row.
- **B.0aa Full-title indexing** — Taxonomy snapshot now indexes `document_type + title` alongside bare titles and aliases, so lawyer-style subordinate-act names (`розпорядження про ...`, `постанова про ...`) can converge without a hardcoded act list.
- **B.0aaa Long-title phrase grounding** — When a near-full official title is queried with omitted stopwords or a shortened legal tail, taxonomy may still ground one subordinate act through phrase-window overlap on `document_type + title`. This keeps long official-title locators deterministic without turning them into broad topical semantic search.
- **B.0aab Descriptive-title acts-search exception** — Strong taxonomy usually skips `lldbi_acts`, but long descriptive/official act-title locators are the exception. They may still run one cheap acts-search pass so the final hit set contains act-level evidence for the same grounded act, not only semantically similar chunks from neighboring primary laws.
- **B.0b Grounded-scope recovery** — If a single-goal run converged to one exact/grounded act but chunks noise still pulled `selected_acts` elsewhere, the finalizer must either recover that same act from its own top-30 chunk evidence or downgrade to low-confidence. U4 must not ship a different final act into writer context for an explicit grounded query.
- **B.0bc Taxonomy-only subordinate recovery** — For explicit grounded subordinate-act queries, if chunk evidence still clusters around near-duplicate repeal/amendment titles but taxonomy converged strongly to one act, finalization may recover that exact subordinate act directly from grounded taxonomy support. This avoids false `likely_missing_act` on acts that do exist in LLDBI while keeping the path deterministic and bounded.
- **B.0bb Metadata-grounded subordinate recovery** — If convergence came from `exact_alias_match` / `exact_title_match` on one subordinate act and that act still has non-trivial top-30 chunk evidence, finalization may recover it under noisy `PRIMARY_LAW` heads using generic evidence thresholds. This prevents false `likely_missing_act` on real grounded subordinate-act titles.
- **B.0c Grounded-scope empty-selection honesty** — If exact/grounded single-act convergence survives taxonomy but final `selected_acts` still becomes empty after scope trim, runtime must emit `*_SCOPE_NO_CONVERGENCE` and move into low-confidence / corpus-gap semantics. `selected_acts=[]` with `coverage_gap=none` is no longer a valid outcome.
- **B.0ca Soft current-law title honesty** — Successor preference is only valid for current-law style title queries without explicit historical pins. If the query names a historical identifier or otherwise distinguishes the predecessor, runtime must keep that historical act family instead of auto-upgrading to the current successor.
- **B.0d Authoritative non-primary scope** — Explicit subordinate-act queries can still resolve confidently even when the dominant source is `SECONDARY_ORDER`. If one non-primary act has strong same-act head evidence and the tail is clearly weaker, finalizer trims to that lead act and clears false `NO_PRIMARY_LAW_EVIDENCE/LOW_EVIDENCE` instead of forcing a fake primary-law requirement.
- **B.0da Strong procedural-support preservation only** — When grounded single-act selection keeps one extra procedural `PRIMARY_LAW`, this is allowed only for real mixed bundles with strong procedural cues (`підслідність`, `оскарження`, `ЄРДР`, document-submission phrasing) plus its own top-30 evidence. Generic wording like `строк` / `термін` / `порядок` alone must not preserve a second code.
- **B.0e Cued numeric act grounding** — Queries like `постанова №1178` or `наказ Мінфіну №1257` now produce grounded act-scope evidence when `document-type cue + sufficiently specific numeric stem` resolve unambiguously to one indexed `rada_nreg`. This happens at taxonomy stage; short or ambiguous bare-number references must remain ungrounded.
- **B.1 Candidate metadata hydration** — Перед `selected_acts` policy runtime добирає `document_type/category/title` з LLDBI cache для актів, які прийшли тільки через chunk evidence. Це прибирає blind spots, коли правильний кодекс потрапив у hits, але виглядав як `UNKNOWN` під час act-kind policy. Runtime: `cache-rag.ts` + `act-taxonomy-store.ts`.
- **B.2 Grounded query builder** — Must-have procedural signals проходять selector-aware filter ще до embed. Якщо query уже grounded (`ст./п./пп./абз./примітка` + act/article cue), runtime не має права роздувати retrieval broad signals типу `строк` або `порядок`; лишаються лише вузькі concepts, що реально допомагають article competition. Runtime: `retrieval/grounded-query-builder.ts`.
- **B.3 Strong taxonomy signal reuse** — Single-goal taxonomy strength (`taxonomy_act_count`, `alias_hit_count`, category/doc-type hints) тепер нормалізований окремим helper і використовується консистентно в rewrite/acts-search policy, щоб cost-saving decisions не розходилися між різними частинами U4.
- **B.4 Single-goal first pass** — Initial single-goal chunks/acts plan і перший Qdrant search винесені в окремий модуль. Strong-taxonomy gate може пропустити eager `lldbi_acts`, але explicit acts-only step request залишається authoritative.
- **C. Within-act chunks** — First pass: unfiltered chunks + acts. When act candidates exist: **per-act retrieval** (top N chunks per act, e.g. 35 per act) so relevant article can appear within act. No hardcode act names.
- **C.2 Article/point backfill** — Для explicit `ст./ч./п./пп./абз.` citation queries U4 після main retrieval робить cheap recovery pass. Спочатку пробує exact structural Qdrant filter; якщо для selector field у cluster немає індексу (`point_number` etc.), runtime падає назад до вузького within-act search + local structural post-filter і лише потім re-rank/noise/diversity. Це дозволяє лагідно пережити payload/index drift.
- **C.1 Within-act act pool assembly** — Single-goal і multi-goal paths будують один і той самий ranked pool актів із taxonomy, bootstrap/acts-search evidence і planner preferences. Мета: не дублювати `lldbi_acts` search перед within-act retrieval, а перевикористовувати first-pass act evidence. Runtime: `retrieval/within-act-pool.ts`.
- **C.1a Conditional within-act fanout** — У single-goal path within-act retrieval тепер gated: weak first-pass (`needTwoStage`) або explicit structural/act anchors. Strong generic runs не повинні платити за per-act Qdrant fanout лише “про всяк випадок”.
- **C.1aa Explicit descriptive act-scope pool rescue** — Якщо query вже виглядає як explicit act locator (`яким наказом...`, `яким розпорядженням...`), але taxonomy ще не має exact grounding, within-act pool не повинен переходити в chunk-evidence-first mode. У таких runs taxonomy-led act pool має шанс провести top subordinate act у filtered same-act search до того, як chunk noise з кодексів витіснить його за ліміт.
- **C.1ab Grounded descriptive-title cheap path** — If taxonomy already grounded one subordinate act from a long descriptive/official title, within-act policy treats that query as act-anchored even without `№` or a compact alias. The runtime stays in a same-act cheap path instead of broad fanout, unless evidence later disproves the grounding.
- **C.1b Within-act expansion policy** — Fanout decision винесений в окремий policy module. Structural/procedural single-goal queries можуть отримати ширший per-act pool навіть на strong first pass, якщо same-act article competition інакше занадто вузький. Те саме policy тепер використовується і в multi-goal per-goal retrieval, тож mixed substantive+procedure bundles більше не йдуть автоматично в старий `top-5 acts per goal` fanout. Runtime: `retrieval/within-act-expansion-policy.ts`.
- **C.1c Grounded structural cheap path** — Якщо selector-heavy query already grounded до одного акту (`КПК ст. 214`, `постанова №... п. 44`), explicit selector сам по собі більше не примушує до широкого act fanout. Такі runs переходять у cheap within-act path, що зменшує `qdrant_calls` без втрати act/article grounding.
- **C.1d Strong-head consensus collapse** — Якщо same single-goal/goal-specific path already має `grounded або explicit act scope` і first-pass chunks повторно підтверджують той самий head act, within-act fanout стискається до одного акту з меншим `chunks-per-act` budget. Це generic optimization для high-confidence same-act runs, не whitelist конкретних актів.
- **D. Hybrid scoring + anti-noise + diversity** — vector + taxonomy alignment + explicit article_ref + structural chunk score. Hybrid score пишеться в `ordering_score`, а `hit.score` лишається сирим vector score для forensics/audit. **Anti-noise penalty** і **diversity cap** працюють поверх `ordering_score`, тобто post-processing не має права стирати rerank назад до vector-only ordering. Secondary-order leakage is further constrained in procedural-dominant traces: repeated evidence alone is not enough without family/hint support. Trace: noise_penalty_policy_version, noise_penalty_guard_blocked, noise_penalty_guard_reason_codes (NO_PRIMARY_ALTERNATIVE, ONLY_SOURCE_FOR_GOAL). Runtime модулі: `retrieval/hit-ranking.ts`, `retrieval/chunk-rerank.ts`.
- **D.0a Grounded act-hit priority** — If taxonomy already grounded one act and `lldbi_acts` returns the same act, hybrid ordering gives that act-level hit extra priority. This is generic retrieval context repair for title-locator queries: writer should see the grounded act itself before drifting into thematically related codes.
- **D.2 Single-goal hit postprocess** — Після within-act fanout single-goal path переходить у окремий postprocess module: hybrid ordering, noise/diversity, reference expansion, article-backfill і final cap. Це тримає `cache-rag.ts` ближче до orchestration-only форми.
- **D.1 Exact point/article dominance** — Якщо query містить explicit structural selector, rerank тепер сильніше винагороджує exact point/subpoint match і штрафує wrong-point lexical overlap. Це важливо для правил/наказів, де в одному акті часто є кілька різних `п. 12`, `п. 15` тощо.
- **E. Hits cap** — Після fusion → noise → diversity cap застосовується u4HitsCap (напр. 100). Trace: hits_total_before_cap, hits_total_after_cap, hits_cap_applied, topN_used_for_distribution, scores_computed_on/avg_score_source = "final_hits_after_cap_and_guards". Cap не впливає на low_confidence (reason_codes не "cap").
- **E.1 Exact single-act scope** — When query plus taxonomy converge to one explicit act identifier and retrieval head confirms the same act, selected-acts policy may trim support tails and suppress false `weak_evidence` caused only by “non-primary-only” heuristics. This is generic behavior for explicit act-scope queries, not a per-act exception.
- **E.1a Grounded single-act scope** — The same low-confidence recovery now applies to compact one-act alias/title queries if retrieval head confirms the exact same subordinate act. This is how `Постанова 1178`-style queries stay truthful without forcing a fake `PRIMARY_LAW` requirement.
- **E.1b Single-act scope module** — Exact/grounded/metadata act-scope trim + recovery is isolated in `retrieval/single-goal-act-scope.ts`, so generalized single-act drift can be tested and debugged independently from the rest of `single-goal-selected-acts.ts`.
- **E.1aa Grounded descriptive subordinate titles** — Metadata-grounded descriptive titles follow the same rule: if exact alias/title grounding converged and same-act evidence survives in top-30, selected-acts policy may recover that act instead of collapsing to empty and surfacing a false corpus miss.
- **E.1ab Anchored metadata grounding without exact equality** — Single-goal act-scope recovery може підтвердити descriptive subordinate act і без `exact_alias_match` / `exact_title_match`, якщо query несе сильний act-reference fragment, candidate already має `title_match`, а `document_type + title` дають стабільний token overlap із act-reference signal. Це generalized metadata-grounding rule, а не per-act exception.
- **E.1ac Distinct-subject guard for metadata grounding** — Token overlap сам по собі не достатній, якщо він складається лише з boilerplate repeal/locator phrasing. Для metadata-grounded single-act convergence потрібні distinct subject tokens із query fragment, інакше runtime має лишатися в weak-evidence / broader-selection режимі замість фальшивого one-act confirmation.
- **E.1ad Low-confidence companion recovery** — Після single-goal narrowing runtime може повернути один compatible `PRIMARY_LAW` companion назад у `selected_acts`, якщо `act_candidates_top` усе ще містить сильний same-family semantic candidate, який material-но сильніший за generic-code fallback. Це generalized `special law + code` recovery, а не per-act exception.
- **E.1ae Metadata-companion fallback guard** — Симетричний honesty guard: якщо single-goal run не має exact/grounded act convergence, але тримається на одному broad chunk-led `PRIMARY_LAW` плюс одному metadata/taxonomy companion `PRIMARY_LAW`, така пара більше не вважається grounded success автоматично. Runtime переводить її в low-confidence path, щоб broad civil/consumer/code substitutes не маскували missing special regime coverage.
- **E.1b Mixed substance+procedure honesty** — In multi-goal runs a single generic procedural primary law can no longer count as full coverage when the goal mix is `procedure + non-procedure` and the act is only chunk-grounded. This blocks false “one KAS/CPC/KPK covers everything” outcomes on missing-special-act queries and lets `coverage_gap` surface `likely_missing_act`.
- **E.1c Single-goal procedural-primary honesty** — In legally specific single-goal runs, if final selection collapses to procedural `PRIMARY_LAW` only and there is no act grounding (`exact_act_hit_count = 0`, `grounded_act_hit_count = 0`, no metadata grounding), runtime must mark the result as low-confidence. Family-level procedural correctness alone is not enough to claim the special act was found.
- **E.1d Low-confidence selected-acts normalization** — After all single-goal scope recovery, a late honesty pass trims or clears `selected_acts` on fragmented / out-of-scope weak-evidence runs. U4 may keep one domain-aligned `PRIMARY_LAW`; otherwise it clears the writer-context act list instead of shipping arbitrary multi-family tails.
- **F. Selective LLM planner** — Тільки за тригерами (multi_goal або contract-like); tier 0/1/2; fallback reason_codes. Не використовується за замовчуванням (U4_PLANNER_ENABLED=false).

## Multi-goal evidence pipeline

- **Goal split** — Heuristic splitter (no LLM by default): multi_question (several "?", "і чия"), multi_topic (criminal+procedure, tax+admin, etc.), contract/table from routing_flags. Cap: goals_max = 3 (config).
- **Contrastive liability compaction** — Запити типу `... коли це адміністративна, а коли кримінальна` мають перетворюватися на компактні aspect-goals, а не на `broad liability + admin + criminal`. Це прибирає зайвий retrieval fanout і фальшиві coverage-miss paths.
- **Anchored-citation split guard** — If the original query already contains explicit structural selectors, heuristic splitting must not create extra goals only because of `і/та`; anchored point/article queries are usually one legal target, not a semantic multi-goal search.
- **Anchored-citation mixed-bundle guard** — Explicit selector queries may still split into substantive+procedure goals, but only when the procedure side carries a strong procedural cue. This prevents same-act citation bundles with generic deadline/process wording from exploding into noisy multi-goal fanout.
- **Act-metadata compaction guard** — `Яким актом... і хто/коли...` compacts only when non-locator clauses are pure act-metadata follow-ups. If the second clause is a real remedy/procedure ask (`як оскаржити`, `куди подавати`), the bundle must stay split.
- **Procedural semantic shaping** — Після structural split goal може отримати `must_have_signals`, якщо з формулювання випливає procedural concept, який часто не названий буквально в title статті: наприклад `хто розслідує ...` → `підслідність`, `внести відомості до ЄРДР` → `початок досудового розслідування`. Це дешевий query enrichment, без окремого LLM hop.
- **Same-act bundle compaction** — Якщо structural split був викликаний лише `і/та`, а сам query виглядає як norm-locator bundle (`де шукати норму про X і норму про Y`, `з яких норм це збирається`), heuristic splitter може згорнути такі clauses назад у single-goal path. Це зменшує qdrant budget і прибирає false multi-goal noise для bundle одного кодексу.
- **Goal split v2 (taxonomy-induced)** — When heuristic yields 1 goal: get taxonomy candidates, then **category-cluster split** (substance vs procedure) from taxonomy + chunks evidence only (no word triggers). Inputs: taxonomy alias_hits by category, chunks evidence distribution in top30. Two strongest clusters: substance (tax_customs/labor_social/civil/criminal/admin) and procedure (judiciary_justice/criminal_procedure/civil_procedure). Split rule: both clusters above threshold, top2 not "other", not direct_citation → 2 goals with required_categories. Trace: goals_summary[].split_source = TAXONOMY_CLUSTER_SPLIT_V2, meta.stage_decisions.goal_split_v2, meta.goal_split_inputs (top_categories, supports).
- **Per-goal act allocation** — When goals_count ≥ 2: act pool per goal filtered by goal.required_categories (from taxonomy alias_hits); minActsPerGoal = 2 when candidates exist; else reason_codes GOAL_ACT_POOL_WEAK. Trace: goals_summary[].act_pool_size, meta.retrieval_debug_bundle.per_goal_act_pool_size.
- **Selective LLM planner** — Only when: multi_goal_detected, or input_is_large && input_looks_like_contract. Returns JSON goals (goal_type, subquery, domain_hint, likely_acts, keywords, why). No article names. Semaphore + circuit breaker (U2); cache in RunContext.
- **Per-goal retrieval** — For each goal: embed(goal.subquery), getTaxonomyCandidates(goal.subquery, goal.domain_hint) filtered by required_categories when set, steps (chunks + acts), within-act, hybrid sort. Tag hits with goal_id.
- **Goal fusion + coverage** — Merge hits; dedupe by r2_key:json_path. Coverage: in top N ensure at least M hits per goal (config u4FusionTopN, u4FusionMinHitsPerGoal). Act diversity cap. Trace: goals_summary, fusion, planner, stage_decisions (used_goal_splitter, used_llm_planner, per_goal_act_retrieval).
- **Selected_acts multi-goal coverage** — When goals_count ≥ 2: minDistinctActs = goals_count (or goals_count+1 if procedure goal); max 8; PRIMARY_LAW priority. Exception: when one PRIMARY_LAW act has dominant early evidence and family conflict is absent, policy may allow single-act coverage for a multi-clause query and trim the noisy tail (`MULTI_GOAL_SINGLE_ACT_COVERAGE_ALLOWED`). If selected_acts still do not cover all goals → reason_codes COVERAGE_MISS_SELECTED_ACTS, low_confidence = true. Trace: selected_acts_decision, selected_acts_confidence, selected_acts_kinds_count.
- **Selected_acts multi-goal coverage** — When goals_count ≥ 2: minDistinctActs = goals_count (or goals_count+1 if procedure goal); max 8; PRIMARY_LAW priority. Exception: when one PRIMARY_LAW act has dominant early evidence and family conflict is absent, policy may allow single-act coverage for a multi-clause query and trim the noisy tail (`MULTI_GOAL_SINGLE_ACT_COVERAGE_ALLOWED`). This exception is blocked when another early `PRIMARY_LAW` from a different legal family already has material chunk evidence, so substantive+procedure queries do not collapse back to one code. If selected_acts still do not cover all goals → reason_codes COVERAGE_MISS_SELECTED_ACTS, low_confidence = true. Trace: selected_acts_decision, selected_acts_confidence, selected_acts_kinds_count.
- **Redundant multi-goal fallback guard** — Навіть коли chunk-only bundle формально покриває всі goals, runtime не вважає його grounded success, якщо surviving acts не дають distinct goal contribution. Такий redundant bundle переходить у `UNGROUNDED_MULTI_GOAL_FALLBACK`, щоб noise repetition не виглядала як реальне multi-act coverage.
- **Goal-aware low-confidence trim** — Early multi-goal tail trim більше не працює як raw evidence sort. Якщо trace already low-confidence і треба зменшити bundle, trim policy все одно зберігає акти з унікальним goal contribution перед тим, як дивитися на `rank_mass_top30` / `best_rank_in_top30`.
- **Family guard evidence floor** — Family/coverage guard не може додавати PRIMARY_LAW акт без material chunk evidence у final retrieval head. Якщо taxonomy family fit є, а retrieval evidence немає, trace мусить дати `FAMILY_GUARD_NO_EVIDENCE`.
- **Selected_acts noise clamp** — Якщо multi-goal query уже має щонайменше два сильні `PRIMARY_LAW` акти, diversity/family guard не повинен реінжектити weak `KSU_DECISION`/`CASELAW_OPINION`/`BILL_DRAFT` у `selected_acts`. Для `SECONDARY_ORDER` support evidence alone also is not enough in procedural-dominant traces; потрібні family/hint signals або non-procedural support, інакше writer отримує шум.
- **Selected_acts weak non-primary tail trim** — Коли multi-goal trace має один домінантний `PRIMARY_LAW` із сильним chunks evidence і на хвості лишається слабкий non-primary акт без explicit source-class hint та без власного material support, policy тепер відсікає цей tail замість удаваного “покриття другої підцілі”. Якщо non-primary type explicitly requested (`Конвенція`, `рішення КСУ`, `постанова`), trim не спрацьовує.
- **Selected_acts final pass after routing** — Routing hints більше не є bypass-каналом повз policy. Late-added acts після family/routing recovery проходять окремий finalizer: unsupported additions без retrieval evidence можуть бути прибрані ще до writer handoff, а confidence піднімається лише коли recovery підтверджений retrieval trace.

## Кроки

1. **U4 event** — після U3a (search_plan + steps у RunContext/RunRecord).
2. **Load run** — RunRepository.findByRunId; search_plan/steps з RunContext або RunRecord.search_plan; query_profile (domain, entities).
3. **ActTaxonomyStore** — getTaxonomyCandidates(query, domainHint, entities). Джерело: Supabase legislation_documents (aliases, keywords, topics, category). TTL refresh; tolerant normalizer (NFC, trim, lower, dedup) for aliases/keywords/topics. getActMeta, scoreActCandidate, findCandidatesByAliasTokens. **Domain-based injection:** якщо domainHint від U2 є і не unknown — snap.byCategory(domainHint) додає до 15 актів категорії (без словників тема→акт).
4. **Domain bootstrap (multi-goal only)** — коли domainHint від U2 слабкий (порожній/general/unknown) і taxonomy candidates слабкі: один додатковий Qdrant acts search (limit 20), гістограма категорій по PRIMARY_LAW з taxonomy; якщо top1_support ≥ 2 і gap ≥ 1 → effective_domain_hint для goal; потім getTaxonomyCandidates(subquery, chosen_family_key). Trace: meta.domain_bootstrap (attempted, used, chosen_family_key, top_categories, reason_codes). Метрики: u4_domain_bootstrap_attempted_total, u4_domain_bootstrap_used_total, u4_domain_bootstrap_conflict_total. Бюджет: максимум 1 acts search на goal.
5. **Query shaping** — NFC, whitespace, typo fix; **anchors тільки з taxonomy**. Без hardcode домен→акт.
6. **Query rewrite policy** — LLM rewrite is budgeted and may be skipped before the call when the query is already strongly anchored by structural citation + act/title cues, або коли single-goal run already has strong LLDBI/taxonomy support (`taxonomy_act_count`, alias hits, category/doc-type hints). Мета: не платити за rewrite там, де deterministic metadata grounding already gives a strong act family and rewrite лише розширює запит та роздуває false multi-goal / multi-query fanout.
7. **Effective query** — нормалізація: короткий query ≤12k; довгий — head+tail (6k+6k).
8. **Embed** — embedQuery(effective) через OpenRouter (openai/text-embedding-3-small, 1536d). При помилці — degraded_sources.lldbi=true, 0 hits, але trace все одно має бути honest: `low_confidence=true`, `coverage_gap=weak_evidence`, `reason_codes+=DEGRADED_LLDBI`, а не мовчазний `coverage_gap=none`.
9. **Qdrant search** — за steps: lldbi_chunks (основне), lldbi_acts (опційно). Timeout + 1 retry. У single-goal path initial `lldbi_acts` search тепер може бути пропущений ще до first pass, якщо taxonomy already дає сильний grounded signal; requested steps для trace/audit при цьому не змінюються.
10. **Within-act retrieval** — якщо є act candidates (taxonomy або acts search) і path справді потребує другого етапу, або query явно заякорений act/structure cues: для top acts — окремий Qdrant search по chunks з filter `rada_nreg = act`, limit ~24 для `single-act strong-head consensus`, ~28 для compact same-act runs, 35 для standard single-goal fanout і 50 для ширших multi-goal pools. Merge + dedupe. Це дає релевантну статтю/пункт/підпункт у межах акту (act→article/point) без обов'язкового fanout на всіх strong generic runs і без старого blind `top-5 acts per goal` behavior.
11. **Hybrid re-score** — ordering без LLM. hit.score у trace залишається векторний.
    `ordering_score` зберігає final retrieval ordering для downstream stages; будь-який post-processing крок має спиратися на нього, а не на raw vector score.
12. **Diversity cap** — у топ 25 не більше 16 hits з одного акту (generalizable). Для structural retrieval cap now keys by full citation path when available, not only by article number.
13. **RawHits** — з payload: r2_key, json_path, score, rada_nreg, article_number, unit_number, unit_type, citation_path, title, source.
14. **Selected_acts (Writer)** — Кожен елемент містить: rada_nreg, act_title, score, why_selected, reason_tag, source_tags; **метадані (E.2):** document_type, category, act_kind (PRIMARY_LAW / SECONDARY_ORDER / CASELAW_OPINION / BILL_DRAFT / UNKNOWN), flags (recovered, keep_one, draft, opinion). Джерело act_kind/document_type/category: taxonomy snapshot + LLDBI metadata hydration для chunk-only acts, щоб policy не втрачала тип правильного акту. **Low confidence (E.3):** коли low_confidence=true, reason_codes містять один з: OUT_OF_SCOPE, NO_STRONG_ACT_EVIDENCE, LOW_EVIDENCE, ACT_SELECTION_LOW_CONFIDENCE (додається автоматично, якщо ще немає).
    `chunks_evidence_top_acts` тепер містить і ранні retrieval signals (`best_rank_in_top30`, `rank_mass_top30`, `max_ordering_score`), щоб policy могла відрізняти “2 дуже сильні top hits” від “8 шумних хвостових hits”.
    Для single-goal запитів policy може залишити один strong supporting secondary act, якщо той має повторний evidence у top-30; це дозволяє зберігати practically relevant orders без повернення до шумного order-dominance.
    Якщо single-goal selection розпадається на кілька різних `PRIMARY_LAW` family без metadata grounding, або head family суперечить конкретному `domainHint`, honesty policy має знизити confidence і передати це далі через `coverage_gap`, а не маскувати cross-family drift як нормальний success.
    Multi-goal policy additionally trims weak off-family `PRIMARY_LAW` tails when dominant primary-law evidence already covers the bundle and the tail has no goal-support, no metadata grounding, and no legitimate procedural-companion role. Це блокує generic cross-family drift without hardcoding concrete acts.
    Якщо ж multi-goal bundle має дві різні `PRIMARY_LAW` family з сильним chunk evidence і повним goal-coverage, сам по собі `family_conflict` уже не примушує run у `low_confidence`: такий conflict вважається поясненим структурою запиту, а не evidence failure.
    After tail trim the runtime recomputes `selected_acts_confidence`, metadata grounding count, `selected_acts_kinds_count`, `selected_acts_document_types_top`, and `coverage_gap` from the final surviving bundle. This prevents stale pre-trim confidence or grounding from leaking into the final trace.
    Multi-goal rewrite variants можна скіпати лише в консервативному випадку: всі goals already have material coverage, кожен goal має explicit `required_categories`, а goal-support покривається category-aligned `PRIMARY_LAW`. Якщо coverage тримається на treaty/off-family tails або goal categories не зафіксовані, variant search не вимикається.
15. **RetrievalTrace.meta** — act_candidates_top, stage_decisions (used_taxonomy, used_acts_search, used_filtered_chunks, used_goal_splitter, used_llm_planner, per_goal_act_retrieval, used_global_fallback), **goals_summary**, **fusion** (coverage_enforced, per_goal_min_hits, topN, per_goal_counts_in_topN), **planner** (tier_selected, called, call_failed_reason, tier, model_id, duration_ms, degraded, reason_codes), **qdrant_calls_count_total**, **hits_total_before_cap**, **hits_total_after_cap**, **hits_cap_applied**, **topN_used_for_distribution**, **scores_computed_on**, **avg_score_source**, **distribution** (noise_penalty_applied_count, noise_penalty_policy_version, noise_penalty_guard_blocked, noise_penalty_guard_reason_codes, hits_by_act_top3, avg_score_by_act_top3), reason_codes, sample_hits, hits_count, low_confidence, coverage_gap, query_variants_used, anchors_used.
    Single-goal trace now also carries `exact_act_hit_count/nregs` and `grounded_act_hit_count/nregs` so explicit-act debugging can distinguish “taxonomy never grounded” from “taxonomy grounded but downstream selection drifted”.
    `acts_search_policy` окремо фіксує, чому eager `lldbi_acts` step був або не був виконаний.
    `within_act_policy` окремо фіксує, чому per-act fanout був або не був включений на цьому run.
    `article_backfill` тепер окремо фіксує, чи recovery path був structural, чи довелося падати назад до post-filter fallback через missing Qdrant index.
    Fast real-dev verifier additionally projects per-case telemetry (`latency_ms`, `qdrant_calls_count_total`, `coverage_gap`, `selected_act_count`, `planner_tier`) into `_reports/retrieval_real_dev_fast_results.json`, щоб regression triage не залежав від ручного `query_retrieval_debug`.
16. **Persist** — RunRepository.updateRetrievalTrace; RunContext: raw_hits + retrieval_trace.
17. **Enqueue U5** — Gate.

## MCP-аудит runs + чанки (read-only)

Скрипт `tools/mcp_audit_runs_chunks_quality.ts` (`pnpm brain:audit:runs-chunks --limit 15 --since-days 3`): тягне runs з Supabase, для кожного — топ 5–8 чанків з retrieval_trace.hits, опційно snippet з R2, пише звіт `_reports/mcp_audit_runs_chunks_quality_YYYY-MM-DD.md`. Таблиця: run_id, query, domainHint, lldbi, selected_acts, low_conf, reason_codes; деталі + юридична оцінка. Для пошуку системних багів.

## Схема

**Single-goal (default):**
```
U3a → [U4] → heuristicGoalSplit(1 goal) → getTaxonomyCandidates → shapeQuery(anchors)
         → embedQuery → Qdrant chunks/acts
         → within-act retrieval (per act, top N chunks) when candidates exist
         → hybrid re-score → diversity cap → RawHits + RetrievalTrace → U5
```

**Multi-goal (when heuristic or LLM planner yields 2+ goals; or single-goal path + tryCategoryClusterSplitV2 yields 2 goals):**
```
U3a → [U4] → heuristicGoalSplit → [if 1 goal: getTaxonomyCandidates → tryCategoryClusterSplitV2]
         → [optional LLM planner if trigger] → for each goal:
         act pool by required_categories (minActsPerGoal=2) → embed(goal.subquery) → getTaxonomyCandidates(goal) → steps → within-act → hybrid
         → merge hits (goal_id) → coverage fusion → diversity cap → buildSelectedActs (minDistinctActs=goals_count, COVERAGE_MISS if not covering) → goals_summary + fusion in meta → U5
```

## Limits

- Qdrant: config.qdrantTimeoutSec, config.u4QdrantConcurrency (no change to DB).
- LLM rewrite/rerank: only on triggers; U4_LLM_* when implemented.

## Деградація

- Embedding failure → degraded_sources.lldbi=true, hits=[], `low_confidence=true`, `coverage_gap=weak_evidence`, U5 все одно enqueue.
- Qdrant unreachable → degraded_sources.lldbi=true, hits=[], `low_confidence=true`, `coverage_gap=weak_evidence`, U5 enqueue.
- Missing-act honesty path: якщо query виглядає юридично конкретним, але LLDBI/taxonomy не сходяться до стабільного act pool і final hits лишаються слабкими/шумними, U4 має ставити `low_confidence=true` і `coverage_gap=likely_missing_act` замість удавано впевненого success. Якщо ж runtime already grounded-ив конкретний indexed акт, але далі не зміг стабільно зібрати `selected_acts`, це має нормалізуватися як `weak_evidence`, а не як хибний сигнал “акту немає в LLDBI”.
- Practical corollary: high hit volume alone is not enough to stay in `weak_evidence`. Якщо legally specific query закінчується лише на слабких non-primary tails без `exact/grounded/metadata` act convergence, normalized outcome має бути `likely_missing_act`, навіть коли retrieval назбирав багато шумних chunks.
- Symmetric corollary: sparse weak non-primary tails are not enough to mark a run as `likely_missing_act`, якщо indexed act grounding already exists. This rule now applies on both single-goal and multi-goal paths through shared `coverage_gap` normalization.
- Multi-goal corollary: `UNGROUNDED_MULTI_GOAL_FALLBACK` now maps directly into `coverage_gap` semantics. Without indexed grounding it becomes `likely_missing_act`; broad taxonomy/framework matches do not suppress this by themselves. To stay in `weak_evidence`, the run needs real indexed grounding (`exact` / `grounded` act hit), not just taxonomy-backed fallback acts.
- Procedural ambiguity corollary: strong indexed procedural surfaces may still normalize to `weak_evidence` even when multi-goal fallback fires. Це відрізняє реальну in-corpus ambiguity між суміжними кодексами від справжнього corpus-gap.
- Broad LLDBI act audits are LLDBI-first measurements: the harness disables DocList and treats selected-act runs with `low_confidence=true` / `coverage_gap!=none` as audit failures, not soft warnings.
- Single-goal honesty reasons на кшталт `COVERAGE_GUARD_FAILED`, `FAMILY_GUARD_NO_EVIDENCE`, `EXPLICIT_ACT_SCOPE_NO_CONVERGENCE`, `NO_ACT_GROUNDING_PROCEDURAL_PRIMARY_ONLY` не повинні “розсмоктуватись” після routing-hints recovery, якщо retrieval не отримав реального act grounding.
- Goal compaction має бути single-act only: якщо query містить кілька сильних act-scope cues (`закон ...` + `постанова №...`), splitter не має зливати такий bundle назад у один goal навіть якщо обидва підпитання виглядають процедурними.
- Exact-act honesty path: якщо explicit act-id query справді конвергує до одного конкретного акту з сильним head evidence, U4 не повинен позначати run як `weak_evidence` лише тому, що акт не є `PRIMARY_LAW`; натомість trace має відобразити confirmed exact-act scope.
- Validation case: `2811-20` (`Про авторське право і суміжні права`) був перевірений у двох станах. До ingest direct copyright-law query чесно переходив у `likely_missing_act`; після ingest через LLDBI CLI той самий query стабільно повертав `2811-20` як primary grounded act.
- Див. `decisions/degraded-policy.md`.
