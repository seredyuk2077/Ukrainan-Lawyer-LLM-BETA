# On-Demand Import — Динамічне додавання документів

## Огляд

On-demand import — це механізм автоматичного додавання нових документів з rada.gov.ua під час роботи системи, коли RAG не знаходить релевантних результатів.

## Коли потрібен on-demand import

### Тригери

1. **Низька впевненість пошуку:**
   - `confidence < 0.6` після гібридного пошуку
   - Мало або немає результатів

2. **Конкретний запит:**
   - Користувач вказав конкретний `nreg` або назву закону
   - Документ відсутній в базі

3. **AI рішення:**
   - LLM визначає, що потрібен конкретний закон
   - Рішення на основі аналізу запиту

### Приклади

```
Користувач: "Що каже закон 435-15 про договори?"
→ nreg "435-15" не знайдено в базі
→ Запускаємо on-demand import

Користувач: "Які права має працівник при звільненні?"
→ Пошук знайшов 2 документи з низькою релевантністю
→ AI визначає: потрібен Трудовий кодекс
→ Запускаємо on-demand import для ТКУ
```

## Стратегія рішення про import

### AI Decision Making

**Модель:** `claude-3-haiku` або `gpt-3.5-turbo`

**Prompt:**
```
Проаналізуй запит користувача та результати пошуку.

Запит: {user_message}
Знайдені документи: {search_results}
Впевненість: {confidence}

Визнач:
1. Чи потрібен імпорт нового документа?
2. Якщо так, який документ потрібен (nreg або назва)?
3. Яка категорія права?

Відповідь в JSON:
{
  "needs_import": true/false,
  "reason": "explanation",
  "suggested_nreg": "435-15" | null,
  "suggested_document": "Цивільний кодекс України" | null,
  "suggested_category": "цивільне" | null,
  "confidence": 0.0-1.0
}
```

### Rule-based перевірки (перед AI)

1. **Якщо `confidence >= 0.7`:**
   - ❌ Не потрібен import (достатньо результатів)

2. **Якщо користувач вказав конкретний `nreg`:**
   - ✅ Перевіряємо чи є в базі
   - ✅ Якщо немає → import

3. **Якщо знайдено 0 документів:**
   - ✅ Можливо потрібен import
   - ✅ AI визначає який

### Safeguards (захист від зловживань)

1. **Rate limiting:**
   - Максимум 5 on-demand imports на користувача на годину
   - Максимум 20 on-demand imports на день (глобально)

2. **Validation:**
   - Перевірка що `nreg` валідний (pattern check)
   - Перевірка що документ існує в rada.gov.ua (404 check)

3. **Розмір документа:**
   - Якщо документ дуже великий (>10MB) → відкладаємо в background job

4. **Черга:**
   - On-demand imports йдуть в чергу
   - Обробка з пріоритетом (user requests > background sync)

## Реалізація

### Синхронний vs Асинхронний

**Синхронний (для швидкої відповіді):**
- Користувач чекає на імпорт
- Використовується для невеликих документів (<1MB)
- Таймаут: 30 секунд

**Асинхронний (background job):**
- Імпорт виконується в фоні
- Користувач отримує відповідь: "Імпортую документ, спробуйте через хвилину"
- Використовується для великих документів (>1MB)

### Синхронний імпорт (швидкий path)

**Процес:**

1. **Визначення `nreg`:**
   - З AI рішення (`suggested_nreg`)
   - Або з витягнутого з запиту користувача

2. **Швидкий імпорт:**
   - Виконуємо кроки 1-8 з паіплайну імпорту (див. `03_ingestion_pipeline.md`)
   - Але з обмеженнями:
     - Пропускаємо детальну AI класифікацію (використовуємо rule-based)
     - Генеруємо embeddings
     - Зберігаємо в R2 та Supabase

3. **Таймаут та retry:**
   - Максимум 30 секунд на імпорт
   - Якщо не встигли → переходимо на асинхронний

4. **Відповідь користувачу:**
   - Якщо успішно → повторний пошук → відповідь
   - Якщо не встигли → "Імпортую, спробуйте через хвилину"

### Асинхронний імпорт (background job)

**Процес:**

1. **Створення завдання:**
   - Додаємо запис в `legislation_import_jobs`
   - Статус: `pending`
   - Тип: `on_demand`

2. **Background worker:**
   - Окремий процес або cron job
   - Бере завдання з `pending`
   - Виконує повний імпорт

3. **Повідомлення користувачу:**
   - При створенні завдання: "Імпортую документ, спробуйте через хвилину"
   - При завершенні: можливо webhook або polling (опціонально)

### Оптимізація для on-demand

**Обмеження AI класифікації:**

- Пропускаємо детальну класифікацію тем (тільки категорія)
- Використовуємо rule-based для типу документа
- Генеруємо embeddings обов'язково (для пошуку)

**Мінімальний імпорт:**

```typescript
{
  // Обов'язкове
  rada_nreg: string;
  title: string;
  category: string;           // Rule-based або з AI
  document_type: string;      // Rule-based
  embedding: number[];        // Генеруємо обов'язково
  
  // Опціональне (можна додати пізніше)
  keywords: string[];         // Можна пропустити для швидкості
  articles: Article[];        // Обов'язково для пошуку статей
  content_hash: string;       // Обов'язково
}
```

## Інтеграція в RAG flow

### Розширений flow

```
Користувач запитує
    ↓
[1] Класифікація питання
    ↓
[2] Гібридний пошук
    ↓
[3] Перевірка результатів
    ↓
    ├─→ Результатів достатньо (confidence >= 0.7)
    │       ↓
    │   Відповідь користувачу
    │
    └─→ Результатів мало (confidence < 0.7)
            ↓
        [4] AI рішення: чи потрібен import?
            ↓
            ├─→ Ні → Відповідь: "Інформації недостатньо"
            │
            └─→ Так → [5] On-demand import
                        ↓
                    [6] Повторний пошук
                        ↓
                    [7] Відповідь користувачу
```

### Edge Function Integration

**В Edge Function:**

```typescript
async function handleUserQuery(userMessage: string) {
  // 1. Класифікація
  const classification = await classifyQuestion(userMessage);
  
  // 2. Пошук
  const searchResults = await hybridSearch(userMessage, classification);
  
  // 3. Перевірка результатів
  if (searchResults.confidence < 0.7 && searchResults.count === 0) {
    // 4. AI рішення про import
    const importDecision = await decideOnImport(userMessage, searchResults);
    
    if (importDecision.needs_import && importDecision.suggested_nreg) {
      // 5. On-demand import
      try {
        await onDemandImport(importDecision.suggested_nreg, {
          sync: true,  // Синхронний для швидкої відповіді
          timeout: 30000
        });
        
        // 6. Повторний пошук
        const newResults = await hybridSearch(userMessage, classification);
        return generateAnswer(newResults);
      } catch (error) {
        // Якщо не встигли → асинхронний
        await scheduleAsyncImport(importDecision.suggested_nreg);
        return "Імпортую документ, спробуйте через хвилину";
      }
    }
  }
  
  // Звичайна відповідь
  return generateAnswer(searchResults);
}
```

## Запис даних після import

### Оновлення БД

1. **legislation_documents:**
   - Новий запис або оновлення (якщо `content_hash` змінився)
   - Статус: `synced`

2. **legislation_articles:**
   - Додавання статей (якщо таблиця використовується)

3. **legislation_import_jobs:**
   - Запис про on-demand import
   - Статус: `completed`
   - Тип: `on_demand`

### Логування

- Тип імпорту: `on_demand`
- Тригери: `low_confidence`, `explicit_request`, `ai_decision`
- Час виконання
- Розмір документа

## Обмеження та обмеження

### Rate Limits rada.gov.ua

- 60 запитів/хвилину
- 100,000 запитів/день
- Пауза 5-7 секунд між запитами

**Наслідки для on-demand:**
- Не можна імпортувати багато документів одночасно
- Потрібна черга для on-demand imports
- Кешування токенів

### Розмір документів

**Обмеження:**
- Синхронний: максимум 1MB (30 секунд таймаут)
- Асинхронний: без обмежень

**Великі документи:**
- Кодекси можуть бути 5-10MB
- Завжди асинхронний імпорт

### Захист від зловживань

1. **Per-user limits:**
   - 5 on-demand imports/годину
   - 20 on-demand imports/день

2. **Global limits:**
   - 20 on-demand imports/день (всього)
   - Після ліміту → черга на наступний день

3. **Validation:**
   - Перевірка `nreg` format
   - Перевірка що документ існує (404 check)

## Моніторинг

### Метрики

1. **Кількість on-demand imports:**
   - За день/тиждень
   - По користувачах
   - По типах тригерів

2. **Час виконання:**
   - Середній час синхронного імпорту
   - Середній час асинхронного імпорту

3. **Успішність:**
   - Процент успішних імпортів
   - Причини помилок

4. **Вплив на RAG:**
   - Чи покращилася впевненість після імпорту
   - Чи з'явилися нові результати

### Алерти

1. **Занадто багато on-demand imports:**
   - Перевищення денного ліміту
   - Можливе зловживання

2. **Високий відсоток помилок:**
   - Проблеми з rada.gov.ua API
   - Проблеми з парсингом

3. **Повільний імпорт:**
   - Середній час > 60 секунд
