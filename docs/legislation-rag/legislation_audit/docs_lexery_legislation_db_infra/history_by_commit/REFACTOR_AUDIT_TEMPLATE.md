## Класифікація Багів

### [ID] A — Ідентифікація / nreg / canonical url / редакції
- **A1)** nreg неправильно розпарсили
- **A2)** переплутали canonical (redirect, інша сторінка)
- **A3)** підхопили не ту редакцію
- **A4)** документ має "картку" + "структуру" і ми беремо не той endpoint

### [ID] B — Визначення типу документа (doc_type)
- **B1)** визначили тип по заголовку і помилились
- **B2)** "Постанова" плутається між КМУ/ВРУ/НБУ/ЦВК
- **B3)** міжнародні (995_/984_) неправильно віднесені
- **B4)** КСУ: "Рішення/Висновок/Окрема думка" змішані
- **B5)** наказ/інструкція/порядок/правила плутаються

### [ID] C — Чинність / validity
- **C1)** не зберігаємо чинність як поле
- **C2)** не відрізняємо "втратив чинність" vs "не набрав чинності"
- **C3)** не фіксуємо date-based validity (valid_from/valid_to)
- **C4)** "чинний у редакції від …" / "частково чинний" — немає представлення

### [ID] D — Структура і нумерація (критично для кодексів)
- **D1)** номер статті береться з індексу масиву (0/1) => зсув
- **D2)** редакційні примітки/виноски/заголовки стають структурними вузлами
- **D3)** "Стаття 115-1", "115¹", "115-2" сортуються/парсяться неправильно
- **D4)** частини ("частина перша/друга…") зливаються або нумеруються неправильно
- **D5)** пункти/підпункти (а), (б) плутаються з абзацами
- **D6)** великі документи ріжуться чанкером так, що губиться "якір" номера

### [ID] E — HTML / форматування / таблиці
- **E1)** таблиці з додатків ламають текст/структуру
- **E2)** нерозривні пробіли, soft hyphen, лапки «», апострофи
- **E3)** переноси рядка руйнують детектор "Стаття/Розділ/Глава"
- **E4)** списки з маркерами плутаються

## План Рефакторингу

### Модулі (мінімально):

1. **Fetcher** — тягне raw HTML/JSON, логує request_url, response_status, final_url_after_redirect
2. **Canonical Resolver** — визначає canonical identifier + canonical URL, "прибиває" редакцію
3. **Metadata Extractor** — витягує issuer, doc_type, title, number, date (doc_type не з заголовка як primary)
4. **Validity Extractor** — витягує чинність, нормалізує в enum (ACTIVE/REPEALED/NOT_IN_FORCE/PARTIALLY_IN_FORCE/UNKNOWN)
5. **Normalizer** — unicode normalization, прибрати NBSP/soft hyphen, уніфікувати тире/лапки
6. **Structure Parser** — будує дерево, НІКОЛИ не нумеруй статті по позиції, номер = з явного маркера
7. **Chunker** — чанкуй так, щоб кожен chunk мав anchors: article_number / section/chapter labels
8. **Validator** — легкі інваріанти (якщо в тексті є "Стаття 115" => має бути вузол article=115)
