## Огляд проблеми

### Поточна ситуація

- **Основна БД:** 2-3k найвживаніших НПА (повні тексти, чанки, RAG embeddings)
- **Проблема:** Інколи потрібен вузький акт, якого немає в основній БД
- **Наслідок:** AI не знає, що документ існує, не може запропонувати його імпорт

### Рішення

**"Document List DB / Catalog"** — окрема база даних з повним списком документів (тільки метадані), щоб AI могла:
1. Знайти кандидат(ів) за запитом користувача
2. Ініціювати on-demand імпорт акту в основну БД
3. Надати користувачу інформацію про наявність документа

### Вимоги до Catalog

- ✅ Повний список документів (всі nreg)
- ✅ Метадані: назва, тип, орган, дата, статус
- ✅ Швидкий пошук (embedding + keywords)
- ✅ Інкрементальні оновлення (delta)
- ✅ Pause/resume для initial load
- ✅ Idempotency (без дублювання)

## Джерела даних

### 1. Open Data Portal — набір даних "docs"

**URL:** `https://data.rada.gov.ua/open/data/docs.json`  
**Файл:** `doc.txt` (TSV формат, Windows-1251)  
**Розмір:** ~50-100 MB (залежить від версії)  
**Оновлення:** Щогодини або частіше

#### Структура файлу `doc.txt`

**Формат:** TSV (табуляція як роздільник)  
**Кодування:** Windows-1251 (потрібна конвертація в UTF-8)  
**Кількість колонок:** 9

| Колонка | Поле | Тип | Опис |
|---------|------|-----|------|
| 0 | `dokid` | Integer | Ідентифікатор документа |
| 1 | `nreg` | String | Номер реєстрації (primary key) |
| 2 | `nazva` | String | Назва документа (Windows-1251) |
| 3 | `status` | Short | Статус документа |
| 4 | `types` | Array/String | Типи документів |
| 5 | `organs` | Array/String | Видавники (органи) |
| 6 | _(порожня)_ | - | Резервна колонка |
| 7 | `minjust` | Byte | Реєстрація в Міністерстві юстиції |
| 8 | `datred` | String | Дата редагування (YYYYMMDD) |

#### Приклад рядка

```
12345	435-15	Про захист прав споживачів	1	[1,2]	[100]		1	20250125
```

**Парсинг:**
- Роздільник: табуляція (`\t`)
- Кодування: Windows-1251 → UTF-8 (через `iconv-lite`)
- Відсутність заголовку: файл починається з даних

#### Оцінка стабільності

✅ **ВИСОКА СТАБІЛЬНІСТЬ:**
- Файл регулярно оновлюється (щогодини)
- Структура не змінюється (9 колонок стабільні)
- Формат TSV простий для парсингу
- Кодування Windows-1251 завжди однакове

⚠️ **РИЗИКИ:**
- Можливі зміни в форматі `types`/`organs` (масиви як рядки)
- Можливі зміни в кількості документів (додавання/видалення)
- Тимчасова недоступність порталу

## Рекомендований формат

### ✅ Рекомендація: Файл `doc.txt` з Open Data Portal

**Обґрунтування:**

1. **Стабільність:**
   - Регулярне оновлення (щогодини)
   - Стабільна структура (9 колонок)
   - Офіційне джерело

2. **Ефективність:**
   - Один файл містить всі документи
   - TSV формат швидко парситься
   - Streaming парсинг можливий

3. **Повнота:**
   - Всі документи в одному місці
   - Метадані достатні для пошуку
   - `datred` для інкрементальних оновлень

4. **Інтеграція:**
   - Вже використовується в `radaDocIndex.ts`
   - Є готовий `OpenDataPortalClient`
   - Підтримка кешування (ETag, If-Modified-Since)

### Fallback стратегія

**Якщо `doc.txt` тимчасово недоступний:**

1. **Використати останній кешований файл:**
   - Зберігати timestamp останнього успішного завантаження
   - Використовувати кеш з `tmp/rada-open-data/doc_index.json`

2. **Спробувати альтернативні джерела:**
   - `/laws/main/r.json` (тільки оновлені)
   - Архівні версії з `/ogd/zak/laws/data/csv/`

3. **Логувати помилку:**
   - Записувати в лог недоступність джерела
   - Пропустити оновлення, продовжити з кешем

4. **Retry логіка:**
   - Exponential backoff (1s, 2s, 4s, 8s)
   - Максимум 3 спроби
   - Після 3 спроб — використати кеш

## Дизайн pause/resume

### Cursor (позиція відновлення)

**Рекомендація:** Використовувати `dokid` як cursor

**Обґрунтування:**
- ✅ `dokid` — integer, легко порівнювати
- ✅ Унікальний для кожного документа
- ✅ Послідовний (зростає з часом)
- ✅ Стабільний (не змінюється)

**Альтернативи:**
- ❌ `nreg` — string, складніше порівнювати
- ❌ Рядок/offset — нестабільний при зміні файлу
- ❌ `datred` — не унікальний (багато документів з однаковою датою)

### Збереження прогресу

**Рекомендація:** Локальний файл `state.json`

**Структура:**
```json
{
  "last_processed_dokid": 12345,
  "last_processed_nreg": "435-15",
  "last_processed_datred": "2025-01-25",
  "total_processed": 5000,
  "total_in_file": 100000,
  "started_at": "2025-01-25T10:00:00Z",
  "last_updated_at": "2025-01-25T12:30:00Z",
  "checksum": "sha256:abc123..."
}
```

**Розташування:** `tmp/rada-open-data/catalog_import_state.json`

**Переваги:**
- ✅ Простий для локального initial load
- ✅ Не потребує БД
- ✅ Легко видалити для restart
- ✅ Можна версіонувати в git (якщо потрібно)

**Альтернативи:**
- ⚠️ SQLite — складніше, але більш надійно
- ⚠️ Supabase таблиця — потребує підключення до БД

### Idempotency

**Механізм:** Перевірка наявності запису перед вставкою

**Стратегія:**
1. **Primary key:** `nreg` (UNIQUE в БД)
2. **Upsert операція:** `INSERT ... ON CONFLICT (nreg) DO UPDATE`
3. **Перевірка змін:** Порівняння `datred` та `content_hash` (якщо є)

**Приклад SQL:**
```sql
INSERT INTO document_catalog (nreg, dokid, nazva, datred, status, types, organs)
VALUES ($1, $2, $3, $4, $5, $6, $7)
ON CONFLICT (nreg) DO UPDATE
SET dokid = EXCLUDED.dokid,
    nazva = EXCLUDED.nazva,
    datred = EXCLUDED.datred,
    status = EXCLUDED.status,
    types = EXCLUDED.types,
    organs = EXCLUDED.organs,
    updated_at = NOW()
WHERE document_catalog.datred < EXCLUDED.datred;
```

**Гарантії:**
- ✅ Повторний запуск не створить дублікатів
- ✅ Оновлення тільки якщо `datred` новіша
- ✅ Можна запускати багато разів без побічних ефектів

## Дизайн інкрементальних оновлень

### Delta файл/endpoint

**Рекомендація:** Використовувати той самий `doc.txt`, але фільтрувати за `datred`

**Стратегія:**
1. Зберігати `last_sync_datred` (остання дата синхронізації)
2. При завантаженні `doc.txt` фільтрувати рядки де `datred > last_sync_datred`
3. Оновлювати тільки змінені записи

**Альтернатива:** Використовувати `/laws/main/r.json` (оновлені документи)

**Порівняння:**

| Критерій | `doc.txt` (фільтр) | `/laws/main/r.json` |
|----------|-------------------|---------------------|
| Повнота | ✅ Всі документи | ❌ Тільки оновлені |
| Швидкість | ⚠️ Потрібен парсинг всього файлу | ✅ Тільки дельта |
| Надійність | ✅ Стабільний формат | ⚠️ Залежить від API |
| User-Agent | ✅ Працює з `OpenData` | ❌ НЕ працює з `OpenData` (403) |
| Пагінація | ❌ Немає | ⚠️ Потрібна (50 елементів за раз) |
| Рекомендація | ✅ Для initial load | ✅ Для delta updates |

**Висновок:** Комбінований підхід
- Initial load: `doc.txt` (повний файл)
- Delta updates: `/laws/main/r.json` (тільки оновлені)
  - ⚠️ Використовувати дефолтний User-Agent (не `OpenData`)
  - ⚠️ Обробляти пагінацію (параметри `from` та `max`)
  - ⚠️ Використовувати `orgdat` або `poddat` замість `datred` для визначення дати оновлення

### Частота запуску

**Рекомендація:** Щоденно (або відповідно до частоти оновлення джерела)

**Розклад:**
- **Initial load:** Один раз (може зайняти кілька годин)
- **Delta updates:** Щоденно о 02:00 UTC (після оновлення джерела)
- **Manual trigger:** Можливий через CLI

**Моніторинг:**
- Логувати кількість нових/оновлених записів
- Алерт якщо delta > 10% від загальної кількості (можлива помилка)

### Обробка видалень/змін

**Видалення документів:**

**Проблема:** `doc.txt` не містить інформації про видалені документи

**Рішення:**
1. **Soft delete:** Додати поле `is_deleted` в БД
2. **Визначення видалень:** Порівняти поточний `doc.txt` з попереднім
   - Якщо `nreg` був в попередньому, але відсутній в поточному → видалено
3. **Оновлення:** `UPDATE document_catalog SET is_deleted = true WHERE nreg NOT IN (...)`

**Зміни документів:**

**Визначення:**
- Порівняння `datred` (якщо змінилась → оновлено)
- Порівняння `content_hash` (якщо є) для точного визначення змін

**Оновлення:**
- Upsert операція (див. вище)
- Оновлювати тільки якщо `datred` новіша

### Стійкість до змін структури

**Валідація перед обробкою:**

1. **Перевірка кількості колонок:**
   ```typescript
   const columns = line.split('\t');
   if (columns.length !== 9) {
     throw new Error(`Invalid column count: ${columns.length}, expected 9`);
   }
   ```

2. **Перевірка типів:**
   ```typescript
   const dokid = parseInt(columns[0], 10);
   if (isNaN(dokid)) {
     throw new Error(`Invalid dokid: ${columns[0]}`);
   }
   ```

3. **Схемний контроль:**
   - Зберігати версію схеми в `state.json`
   - При зміні схеми — логувати попередження
   - Можливість ручного оновлення парсера

**Fallback:**
- Якщо структура змінилась — зупинити обробку
- Зберегти помилкові рядки в `tmp/rada-open-data/errors.jsonl`
- Логувати деталі для ручного аналізу

## Структура даних Catalog Record

### Мінімально необхідні поля

**З джерела (`doc.txt`):**
- `dokid` (Integer) — ідентифікатор документа
- `nreg` (String, UNIQUE) — номер реєстрації (primary key)
- `nazva` (String) — назва документа
- `datred` (Date) — дата редагування (YYYY-MM-DD)
- `status` (Short/Integer) — статус документа
- `types` (Array/String) — типи документів
- `organs` (Array/String) — видавники (органи)
- `minjust` (Byte/Boolean) — реєстрація в Міністерстві юстиції

**Додаткові поля (наші):**
- `created_at` (Timestamp) — дата створення запису в каталозі
- `updated_at` (Timestamp) — дата останнього оновлення
- `is_deleted` (Boolean) — чи видалено документ
- `embedding_text` (String) — текст для embedding (генерується)
- `embedding` (Vector) — векторне представлення (pgvector)
- `keywords` (Array<String>) — ключові слова для пошуку

### Embedding text (що піде в вектор)

**Рекомендований формат:**
```
{nazva} | Тип: {types} | Орган: {organs} | Дата: {datred}
```

**Приклад:**
```
Про захист прав споживачів | Тип: Закон України | Орган: Верховна Рада України | Дата: 2025-01-25
```

**Обґрунтування:**
- Назва — найважливіша частина для пошуку
- Тип та орган — допомагають розрізняти схожі документи
- Дата — для фільтрації за актуальністю

**Альтернатива (розширена):**
```
Документ: {nazva}
Тип: {types}
Видавник: {organs}
Дата редагування: {datred}
Статус: {status}
```

### Metadata (що піде в metadata для пошуку)

**Структура:**
```json
{
  "nreg": "435-15",
  "dokid": 12345,
  "type": "Закон України",
  "organ": "Верховна Рада України",
  "datred": "2025-01-25",
  "status": 1,
  "minjust": true
}
```

**Використання:**
- Фільтрація за типом документа
- Фільтрація за органом
- Фільтрація за датою
- Точний пошук за `nreg`

### 2. Утиліти

**Розархівація:**
- `unzipper` (вже використовується в `openDataPortalClient.ts`)
- Розпакування ZIP → TSV файл

**Конвертація кодування:**
- `iconv-lite` (вже використовується в `radaDocIndex.ts`)
- Windows-1251 → UTF-8

**Streaming парсинг:**
- `ReadableStream` для великих файлів
- Парсинг по рядках (не завантажувати весь файл в пам'ять)
- Batch обробка (100-1000 записів за раз)

**Приклад:**
```typescript
const stream = response.body;
const reader = stream.getReader();
const decoder = new TextDecoder('utf-8');
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop() || ''; // Залишаємо неповний рядок
  
  for (const line of lines) {
    if (line.trim()) {
      const entry = parseDocLine(line);
      if (entry) batch.push(entry);
    }
  }
  
  if (batch.length >= 1000) {
    await processBatch(batch);
    batch = [];
  }
}
```

## Висновки

### ✅ Рекомендації

1. **Джерело:** Файл `doc.txt` з Open Data Portal (набір даних "docs")
2. **Формат:** TSV, Windows-1251 → UTF-8
3. **Initial load:** Повний файл з pause/resume через `dokid`
4. **Delta updates:** `/laws/main/r.json` (оновлені документи)
5. **Збереження стану:** Локальний файл `state.json`
6. **Idempotency:** Upsert через `nreg` (UNIQUE)

### ⚠️ Ризики

1. **Зміна структури:** Валідація перед обробкою
2. **Тимчасова недоступність:** Fallback на кеш
3. **Великий розмір файлу:** Streaming парсинг
4. **Видалення документів:** Soft delete через порівняння версій
5. **Delta endpoint User-Agent:** `/laws/main/r.json` не працює з `User-Agent: OpenData` (403)
6. **Пагінація delta endpoint:** Потрібна обробка пагінації для отримання всіх оновлених документів

### 🎯 Наступні кроки

1. ✅ Каталог актів працює в **Qdrant** (`legislation-catalog-index`) — Cloudflare Vectorize більше не використовується
2. Створити SQL схему для `document_catalog` (якщо потрібно для додаткового зберігання)
3. Реалізувати парсер `doc.txt`
4. Реалізувати initial load з pause/resume
5. Реалізувати delta updates
6. Інтегрувати в Edge Function для AI-пошуку
